# Bricko Voice Core

Voice agent that answers inbound WhatsApp Business calls. Meta routes the call over SIP to the
Asterisk gateway in `gateway/`, which hands the audio to this Node.js/TypeScript service over
AudioSocket; the service talks to Google Gemini Live and plays its replies back to the caller.

## What it does today
- Answers inbound WhatsApp calls routed by Meta over SIP/TLS (SRTP with SDES keys, Opus audio).
- Streams the caller's audio (8 kHz PCM) to Gemini Live and plays Gemini's replies back,
  resampled from 24 kHz to 8 kHz and sent in real-time 20 ms frames. Queued reply audio is
  dropped when the caller interrupts.
- Speaks as the persona defined in `src/prompts.ts` (Hindi / Hinglish / English real-estate
  advisor); the Gemini voice is set by `GEMINI_VOICE` (default `Charon`).
- Ends the call itself: after its farewell the model calls an `end_call` function, and the
  agent hangs up once the farewell has finished playing.
- Keeps a record per call: caller details from Meta's SIP headers, received / answered /
  connected / ended times, duration, end reason and a two-sided transcript, written to the
  log as one `CALL_RECORD` JSON line (see [Call Records](#call-records)).
- Takes every setting from `.env` (agent) and `gateway/.env` (gateway); see the `.env.example`
  files. Each source file is kept under 100 lines.

## Known limitations
- Call records exist only in the agent's log; nothing is written to a database.
- Calls are not audio-recorded (only the text transcript is kept), although the greeting says
  the call is being recorded.
- Transcripts come from Gemini's live transcription and can contain recognition errors;
  Hinglish may come back in Devanagari or Latin script. Turns are kept in order only, with no
  per-turn timestamps.
- The persona prompt mentions specific projects, site visits and sharing details on WhatsApp,
  but the agent has no project data and cannot send WhatsApp messages: prices or availability
  it states are generated by the model, and the WhatsApp follow-up its farewell promises is
  not sent.
- No memory across calls: each call starts without knowledge of earlier calls or chats.
- Inbound calls only; long calls are not protected against Gemini Live session limits.

## Planned (not implemented yet)
- Store call records in Postgres, linked to the existing `leads` table by phone number, with
  JSONB columns for caller/business details, transcript, call quality and AI usage.
- Audio recording of calls (stereo: caller and AI on separate channels) stored on AWS S3,
  then post-call transcription of the recording for word-level timestamps on both sides.
- Tools for the model: project/brochure lookup from Brickfolio's own data, optional web
  search, sending a brochure on WhatsApp, scheduling a site visit.
- Memory across calls and chats: load the lead's existing context when a call starts.
- Session resumption for long calls.
- Persona prompt and greeting loaded from configuration instead of source code.
- Per-call audio quality (jitter, packet loss) and Gemini token usage in the call record.
- Production deployment on AWS (the current GCP VM is a proof of concept).

## Quick Start (local)
```bash
cp .env.example .env      # set GEMINI_API_KEY
npm install
npm run dev               # starts the AudioSocket server and the caller-details endpoint
npm run test:call         # in another terminal: connects like Asterisk and counts the greeting audio
```
`test:call` sends no caller speech or call UUID, so it only checks that the agent answers and
Gemini produces the greeting.

## Architecture
```text
WhatsApp caller → Meta (SIP/TLS + SRTP-SDES, Opus) → Asterisk gateway (gateway/)
               → AudioSocket TCP (8 kHz PCM) → Bricko Voice Core (src/) → Gemini Live
               (caller details: gateway → HTTP POST on loopback → agent)

src/
├── api/              # AudioSocket TCP server, caller-details HTTP endpoint
├── calls/            # Caller details, transcript, call record and record sink
├── voice/            # Gemini Live provider, audio playout/resampling, call orchestration
├── infrastructure/   # Typed configuration (.env) and logger
├── prompts.ts        # Persona prompt and greeting
└── main.ts           # Service entry point

scripts/              # test-call (local smoke test), configure-meta-sip (Meta SIP settings)
gateway/
├── templates/        # Asterisk configs, rendered from gateway/.env at container start
├── entrypoint.sh     # Validates env + TLS files, renders templates, starts Asterisk
└── docker-compose.yml
```

## Call Records
For every call the gateway posts the caller's details (number, WhatsApp name, country,
WhatsApp call/user IDs, business number IDs, SIP call ID, received/answered times) to the
agent's loopback endpoint (`METADATA_*` in `.env`, `AGENT_METADATA_URL` in `gateway/.env`)
before audio starts. When the call ends the agent logs one `CALL_RECORD {…}` JSON line with
those details, connect/end times (UTC), duration, end reason and the two-sided transcript
(`lead` / `bricko` turns in spoken order). Set `CALL_LOG_TRANSCRIPTS=true` to also log turns live,
and `LOG_TIMEZONE` for readable log times.

## WhatsApp Gateway Deployment (VM)
1. Point a DNS A record (e.g. `sip.yourdomain.com`) at the VM's public IP.
2. Get a certificate for it from a public CA and copy `fullchain.pem` + `privkey.pem` into
   `gateway/certs/`. On shared free domains, check the parent domain's CAA record and the CA's
   rate limits first (the current setup uses acme.sh with Google Trust Services).
3. `cp gateway/.env.example gateway/.env` and fill in the values; open the TLS port and the RTP
   UDP range in the VM firewall.
4. Start the agent on the same VM with `HOST=127.0.0.1` (`npm run build && npm start`, or under
   pm2), then the gateway: `cd gateway && docker compose up -d --build`.
5. Verify TLS: `openssl s_client -connect sip.yourdomain.com:5061` should show your certificate.
6. Register the gateway with Meta: `npm run meta:sip` (dry run), then `npm run meta:sip -- --apply`.
7. Call the number from WhatsApp and watch the agent log and `docker logs -f bricko-whatsapp-gateway`.
